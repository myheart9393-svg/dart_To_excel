# DART → Excel Converter

DART 보고서 URL(또는 14자리 접수번호 rcpNo)을 입력하면 재무제표(재무상태표·손익계산서·포괄손익계산서·자본변동표·현금흐름표)와
재무제표 주석 전체를 파싱하여, 재무제표는 표별로, 주석은 주석번호별로 **각각 별도 시트**로 나눈 `.xlsx`를 내려주는 Streamlit 앱입니다.

**지원 문서**: 사업·분기·반기보고서(K-IFRS 연결/별도), 감사보고서(K-IFRS, 일반기업회계기준) — 실검증 문서 3건
(삼성전자 사업보고서 20260310002820, 리벨리온 연결감사보고서 20260414001300, 나이키코리아 감사보고서 20260911000443).
배치 검증 300건: 정상률 90%(1차 표본 150건)/87%(2차 표본 150건) — 아래 [배치 검증](#배치-검증-개발용) 절 참고.

## 설치

```bash
uv sync --extra dev          # Python 3.11+ (3.14에서 확인)
```

uv가 없으면:

```bash
python -m venv .venv
.venv/Scripts/activate        # Windows
pip install -e ".[dev]"
```

## 실행

```bash
uv run streamlit run app.py
```

브라우저에서 열리는 화면에 URL 또는 rcpNo를 넣고 **변환 시작**을 누르면 진행률과 단계 문구가 표시되고,
완료 후 **Excel 다운로드** 버튼과 결과 요약(재무제표 종류·행 수, 주석 개수·번호 범위, 경고 목록)이 나옵니다.
"주석을 주석번호별 시트로 분리" 체크를 끄면 `주석_전체` 시트만 만듭니다.

## 입력 형식

| 형식 | 예 |
|---|---|
| 뷰어 URL | `https://dart.fss.or.kr/dsaf001/main.do?rcpNo=20240312000736` |
| 본문 URL | `https://dart.fss.or.kr/report/viewer.do?rcpNo=…&dcmNo=…` |
| 접수번호만 | `20240312000736` |

앞뒤 공백·따옴표는 무시합니다. 사업/분·반기보고서(연결+별도)와 감사보고서(단일 또는 연결) 모두 지원합니다.

## 출력 규격

파일명: `{회사명}_{보고서명}_{rcpNo}.xlsx` (회사명·보고서명을 못 찾으면 생략).

| 시트 | 내용 |
|---|---|
| `목차` | 시트명(하이퍼링크)·구분·스코프·원문 제목·행 수, 그리고 경고 목록 |
| `정보` | rcpNo, 회사명, 보고서명, 기준일, 파싱 시각, 원본 URL, 재무제표 수, 주석 수, 스코프 |
| 재무제표 | 표 하나 = 시트 하나. 연결·별도가 모두 있으면 `연결_재무상태표`, `별도_재무상태표`처럼 접두어, 하나뿐이면 `재무상태표` |
| 주석 | 주석번호 하나 = 시트 하나. `주석01_일반사항`, `연결주석21_우발부채와약정사항` (31자 제한) |
| `주석_전체` | 모든 주석을 원문 순서대로 이어붙인 시트 (검색용). 스코프가 둘이면 `연결주석_전체`, `별도주석_전체` |

재무제표 시트는 1행 제목, 2행 기간, 3행 단위, 5행부터 헤더(다단 헤더는 병합)와 본문입니다.
금액은 숫자형(`#,##0;(#,##0);"-"`)이고 계정과목은 원문 들여쓰기를 셀 indent로 유지합니다.
주석 시트는 문단·하위 제목·표를 원문 순서대로 놓고, 표 위에 캡션과 `(단위: …)`를 둡니다.

### 주석참조 열
계정과목 끝에 `(주4,29)`, `(주석3, 20)`, `(주석 3~5)` 가 붙어 있으면 계정과목에서 떼어 바로 뒤 **주석** 열(문자열 `4,29`)로 넣습니다.
감사보고서처럼 원문에 이미 `주석` 열이 있는 표는 그대로 둡니다. 주석 본문 안의 표에도 같은 규칙이 적용됩니다.

### 검증 경고의 의미
`목차` 시트와 화면의 경고 목록에 다음이 나오면 **파싱 결과를 의심**하고 원문과 대조하세요.

| 경고 | 의미 |
|---|---|
| `재무상태표(…) …: 자산총계 X ≠ 부채 Y + 자본 Z (차이 D) — 파싱 오류 가능` | 열 하나에서 대차가 맞지 않음. 행이 밀렸거나 숫자가 잘못 읽혔을 가능성 |
| `재무상태표(…) 대차 검증 불가: … 행 없음` | 총계 행을 찾지 못해 검증하지 못함 (계정명이 특이한 경우) |
| `주석 N 누락 …` / `주석 N 초과 검출 …` | 문서 트리의 주석 목록과 검출 결과가 다름. 자식 노드를 개별 수신해 보정 |
| `주석 표 N개에서 숫자 열에 문자열 값이 섞여 …` | 텍스트·숫자 혼합 표. 값은 문자열로 보존됨 (정상인 경우가 많음) |
| `이 공시에 정정본이 있습니다: … (rcpNo=…)` | 정정공시가 있음. 아래 참고 |

현금흐름표는 회사마다 소계 구조가 달라 검증하지 않습니다.

### 정정공시
변환은 **입력한 rcpNo 의 문서** 기준입니다. DART 본문선택 목록에 정정본이 있으면 경고로 알려주며,
정정본 rcpNo 를 직접 입력하면 정정본이 변환됩니다.

## 제한사항

- **로그인이 필요한 문서**(비공개·기업 내부 열람용)는 받을 수 없습니다.
- **이미지로 된 표**는 텍스트가 없어 파싱되지 않습니다.
- **XBRL 은 사용하지 않습니다.** 뷰어 HTML 을 그대로 파싱하므로 회사마다 표 모양이 다를 수 있습니다.
- **정정공시는 입력한 rcpNo 기준**입니다. 최신 정정본을 원하면 정정본의 rcpNo 를 입력하세요.
- viewer.do 는 `offset`/`length` 를 무시하고 `eleId` 단위로 응답하므로, 감사보고서처럼 재무제표 노드에 주석이 포함되면 HTML 안에서 주석 시작 지점을 찾아 잘라냅니다.
- 주석 표는 텍스트·숫자 혼합이 흔합니다. 숫자로 읽지 못한 값은 문자열로 그대로 남기고 경고 1줄로 집계합니다.
- DART 가 요청을 거부하면(차단 문구·빈 응답) "DART가 요청을 거부했습니다" 메시지가 뜹니다. 잠시 후 다시 시도하세요.

## 배치 검증 (개발용)

DART 공시목록 API로 접수번호를 대량 수집해 변환기를 돌리고, 실패·경고를 코드로 분류해 파서 약점을 통계로 찾는 도구입니다. 앱과 분리되어 있습니다.

1. https://opendart.fss.or.kr 에서 API 키를 발급받아 `.env` 에 `DART_API_KEY=...` 로 저장합니다 (`.env.example` 참고. 키는 커밋·로그에 남지 않습니다).
2. 실행 순서:

```bash
uv run python scripts/batch_collect.py    # batch/targets.csv 수집 (기본 최근 18개월, seed 42)
```

```bash
uv run python scripts/batch_run.py        # 변환 실행. 원본 HTML 을 batch/cache/ 에 저장
```

```bash
uv run python scripts/batch_report.py     # batch/summary.md, batch/fixture_candidates.md 생성
```

파서 수정 후에는 `batch_run.py --offline` 으로 네트워크 없이 캐시로 재실행합니다.
분류 코드 의미는 `scripts/batch_classify.py` 의 `CODE_DESCRIPTIONS` 에 있습니다. `batch/` 는 커밋되지 않습니다.

### 검증 결과 (2026-09, 표본 300건)

| 표본 | 정상 | 문서 특성 실패* | 파서 결함 실패 |
|---|---|---|---|
| 1차 150건 (seed 42) | 135 (90%) | 5 | 0 |
| 2차 150건 (seed 43, 중복 없음) | 131 (87%) | 8 | 0 |

\* `E_NO_CONTENT`: 재무 내용이 없는 공시(정정신고·제출기한 연장·관련 공시, 표 없는 첨부) — 앱은 원인과
다음 행동(원 공시 rcpNo)을 안내합니다. 정상이 아닌 나머지 성공 건의 경고도 대부분 문서 특성이거나
**문서 오류 탐지**입니다: 대차 불일치 경고 2건은 공시 원문 수치 자체가 안 맞는 문서였고(파싱은 정확),
주석 번호 누락 경고는 원문 오타(`78.`, `12<마침표 없음>`)나 실제 미기재를 그대로 드러낸 것입니다.

## 구조

| 파일 | 역할 |
|---|---|
| `app.py` | Streamlit UI (파싱 로직 없음, `pipeline.convert_report` 만 호출) |
| `dart/fetcher.py` | HTTP 세션·헤더·인코딩·재시도 (네트워크 호출은 여기에만) |
| `dart/tree.py` | main.do → 문서 트리, 대상 노드 선택, 입력 해석 |
| `dart/tables.py` | HTML table → 2D grid, 숫자 정규화, 단위 추출 |
| `dart/statements.py` | 재무제표 식별·추출 (감사보고서는 주석 시작에서 절단) |
| `dart/notes.py` | 주석을 주석번호 단위로 분할 |
| `dart/excel.py` | openpyxl 워크북 작성, 시트명 규칙, 스타일 |
| `dart/pipeline.py` | 입력→fetch→tree→파싱→excel 오케스트레이션 (`convert_report`) |
| `dart/models.py` | dataclass 정의 |
| `tests/` | fixtures 기반 pytest (`tests/fixtures/*.html` 은 실제 DART 저장본) |
